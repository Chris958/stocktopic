# AI Token用量与降耗策略

## 范围

项目只有三类任务会调用OpenAI Responses API。Tushare行情、猫爪Level-2、资金委托分析、
测试票池、题材评分、数据库处理和企业微信群机器人推送都不消耗大模型Token；这些服务中的
`token`或API Key只是访问凭据，配额和计费由各数据商单独决定。

| AI任务 | 触发条件 | 当前上限 | 保留理由 |
|---|---|---:|---|
| `semantic_event_clustering` | 当日合格强势股票的代码、原因或题材证据发生变化 | 6次联网工具调用、8,000输出Token | 跨标签聚合是初期识别PTFE、AI漫剧等新逻辑的核心，过度裁剪会漏题材 |
| `admission_analysis` | 新候选首次审查、失败30分钟后重试，或早期观察出现新催化 | 5次联网工具调用、6,000输出Token | 需要同时核验90自然日窗口、新催化、持续性、空间情景和反证 |
| `catalyst_refresh` | 早期观察早盘前及收盘后；正式题材仅收盘后 | 3次联网工具调用、3,500输出Token，低搜索上下文 | 只是例行补充新闻，不参与第一次共同事件成组 |

输出上限包含模型可见输出及推理Token，是防止异常长响应的预算边界，并不表示每次都会用满。

## 已实施的降耗

- 共同事件缓存签名只在股票代码、涨停原因或题材证据变化时失效；封板变炸板等盘中状态变化
  不再重复调用AI，页面中的板块状态仍使用最新行情重新计算。
- 待审题材不再额外执行催化刷新，因为准入审查本身已经联网核验催化。
- 早期观察从最多每日4次催化搜索调整为2次；正式题材调整为1次。
- 催化刷新没有新增证据时，不再无条件重新执行完整准入审查。
- 现有催化由最多12条压缩到6条；扩池白名单由最多160只压缩到80只，并只传代码、名称和
  匹配标签；成员证据去掉市值、行情和重复字段。
- 固定指令放在动态题材数据之前，并设置任务级`prompt_cache_key`，提高相同任务的前缀缓存机会。
- 上游不支持缓存键或联网次数上限时，会自动协商为兼容模式；不会因为降耗参数造成任务失败。

按调度上限计算，例行催化刷新从原来的最多`8题材 × 4时段 = 32次/交易日`降为最多16次；
原来每轮刷新后可能附带的早期观察完整准入调用，现在仅在确实写入新催化时发生。因此实际
降幅取决于当天早期观察/正式题材数量和新增新闻数量，不能在没有生产usage数据时伪造固定比例。

## 查看真实用量

升级后，每次成功AI响应都会写入`ai_usage_events`。运行：

```bash
curl -s http://127.0.0.1:8765/health | python3 -m json.tool
```

查看`ai_usage.last_24h`和`ai_usage.last_7d`：

- `calls`：成功请求数；
- `reported_calls`：上游实际返回usage的请求数；
- `input_tokens`、`cached_input_tokens`、`output_tokens`、`reasoning_tokens`、`total_tokens`：
  上游返回的真实计数；
- `prompt_chars`：所有请求都会记录，用于上游不返回usage时做规模对比，但不会冒充Token；
- `web_search_calls`：模型实际发起的联网工具调用次数；
- `by_task`：按三类任务拆分。

只有`usage_complete=true`时，窗口内Token总数才是完整统计。中转服务不透传usage时，系统会将
它明确标为不完整。

## 进一步降低成本的选择

系统支持按任务配置模型，留空时继续使用`OPENAI_MODEL`：

```dotenv
OPENAI_MODEL=gpt-5.6-sol
OPENAI_CATALYST_MODEL=中转支持的低成本模型
OPENAI_ADMISSION_MODEL=gpt-5.6-sol
OPENAI_CLUSTER_MODEL=gpt-5.6-sol
```

推荐只先下调`OPENAI_CATALYST_MODEL`。例行新闻摘要结构固定、风险较低；共同事件聚类和准入决定
直接影响漏报与误报，继续使用强模型更稳妥。具体低成本模型名称必须以当前中转服务支持列表为准，
系统不会擅自填写一个可能不存在的模型。

若后续仍需显著降耗，更优的架构是先把新闻订阅落库并做本地向量检索，只把与当日股票原因最相关
的少量证据交给强模型；或用低成本模型做第一次聚类，再让强模型只复核达到4票硬门槛的组合。
这两种方案需要新增新闻库/模型服务和历史回测，不能在没有验证召回率前直接替代当前识别链路。
