# V11共同事件、分级准入与题材Level-2资金流向规格

## 产品目标

系统只识别“刚开始形成资金共识、具备持续性的新重点题材”，不向用户罗列普通个股异动、小题材或反复轮动的旧题材。

- 市场：沪深主板与创业板；排除科创板、北交所、ST及退市整理股票。
- 行情：Tushare `rt_k` 每5分钟；开盘啦涨停与概念接口提供题材、涨停原因和股票池。
- 展示：网页不提供个股异动池。底层异动仅保留给龙头带动、风险评分和审计。
- 历史：以最近60个交易日（约90个自然日）判断同逻辑是否已经发酵或反复炒作；窗口外网页历史只作背景，不能否决当前新事件。每次启动和收盘后重放最近2个交易日的发现链路。

## Level-2主动委托资金

- 数据源：猫爪`level2_trade_history`与`level2_order_history`，只使用官方HTTPS公网接口；
- 统计单位：主动方委托号，不以孤立成交记录作为大单；
- 主动买入：按`buy_order_id`累计该委托所有有效成交；
- 主动卖出：按`sell_order_id`累计该委托所有有效成交；
- 大单：累计主动成交金额不低于50万元；超大单：不低于100万元；
- 买入占比：同一门槛下主动买入金额÷主动买卖金额合计；
- 净主动流入：同一门槛下主动买入金额－主动卖出金额；
- 未知方向、缺少主动方委托号及取消类零金额记录不进入资金比例，并单独披露覆盖率；
- 逐笔委托原始`side/order_type`先保留审计分布，待沪深真实样本校准后再识别撤单；
- 页面按需分析，首版保存汇总而不保存全日原始逐笔，避免数据库无界膨胀。

## 第一层：数据质量门禁

- `pre_close<=0` 或 `close<=0` 的行情不可用于涨跌幅、异动或题材判断。
- 集合竞价暂无有效价格时跳过该股票；绝不把 `close=0` 计算为 `-100%`。
- 连续交易阶段有效主板与创业板行情低于当前有效股票池80%（且至少2000只）时熔断本周期，并生成企业微信群机器人数据故障告警。
- 全市场累计成交额和成交量未变化时判定数据陈旧，禁止生成机会信号。
- 升级数据库时清理历史 `close<=0` 快照及 `pct_change<=-99` 异动记录。

## 第二层：共同事件四票门槛

- 输入为当日主板涨停/炸板股票，以及创业板盘中最高涨幅严格超过10%的股票；后者按等效强势信号计入，不等同于交易所涨停。
- 先逐只核查上涨原因，再附加开盘啦标签、题材成分、公司业务关联和当日/隔夜新闻进行聚合；缺少开盘啦原因的创业板股票必须由业务关联与新闻补齐，不能仅按涨幅凑数。
- 通过语义聚类寻找“同一个具体催化事件或新增产业逻辑”，标签文字可以不同；宽泛行业标签不能作为共同事件。
- 同一共同事件当日累计至少4只股票形成上述强势信号，才允许创建准入候选。
- 当前炸板股票与创业板涨幅超过10%股票计入4只门槛，但封板数、创业板强势数、炸板数和首次信号时间分别保存。
- 同一股票在同一事件中只计一次；语义层不得加入输入集合外的股票，也不得用宽泛关联凑足4只。
- 不设每轮候选数量上限。所有达到4票门槛的候选都创建持久记录，保存聚类方法、成员证据和后续审查结论。
- AI聚类不可用时，系统以共同开盘啦标签作明确标注的降级分组，并在30分钟后重试；不会阻塞行情采集。

## 两交易日回补

- 服务调度器启动后自动同步并重放最近2个交易日的开盘啦涨停/炸板、题材成分及创业板强势数据。
- 每个交易日收盘校准后再次重放最近2个交易日，再执行候选准入。
- 回补使用日度开盘啦接口和Tushare `daily` 正式日线最高价，不调用 `rt_k`，因此不破坏实时行情的交易时段闭锁。
- 相同交易日、共同逻辑和成员集合使用稳定指纹，重复回补只更新证据，不重复创建题材或推送。

## 第三层：60交易日新颖性审查

系统向AI提供候选题材、强势股票、窗口内历史相似题材及股票重合度。AI必须搜索公开信息并判断：

1. 是否为新的最小共同炒作逻辑；
2. 是否只是旧题材换名、新新闻刺激或反复轮动；
3. 当前催化与过去60个交易日的核心区别；
4. 存在哪些反证和证伪条件。

判为复炒时必须引用系统提供的60交易日窗口内历史题材ID。只在网页搜索中发现的更早历史不能作为否决证据；若AI未提供有效窗口内ID，系统自动撤销“旧题材”否决。大类概念过去存在，但本次出现新的具体事件并首次形成当期广泛共识，仍可判为新题材。

自动准入要求 `is_new_theme=true` 且新颖性置信度不低于70。

## 第四层：催化与持续性审查

- 催化可信度不低于65；
- 至少保存一条由Web搜索实际返回、带原始URL、标记为“明确证据”的催化；
- 预估持续至少3个交易日，或龙头候选的有条件情景空间至少30%；
- 龙头代码必须来自触板股票或确定性股票白名单；
- 30%是情景空间，不是目标价，必须同时保存成立条件和反证。

任一关键门槛失败，候选转为不准入状态，不进入题材库，也不推送新题材提醒；但记录和具体失败项继续在页面“未入池”筛选中可见。

## 第五层：证据分级

- **早期观察**：四票市场共识、新颖性、催化可信度和持续性均通过，但当前只有供应链消息、研报或单一来源，尚缺官方确认或多源产业证据。创建观察记录并发送“早期观察”群机器人消息。
- **正式题材**：上述条件通过，且至少有官方/公司披露，或带两个以上独立来源域名的多源产业证据交叉验证。升级正式题材、计算评分并发送“正式题材”群机器人消息。
- 早期观察在定时新闻更新后自动重新审查；证据增强可升级正式题材，证据仍不足时保留观察状态和最新原因。
- 英伟达PTFE类“5只触板、共同事件清晰、供应链证据明确但尚无英伟达官方确认”的场景，应先进入早期观察，而不是直接消失或冒充正式确认。

## 第六层：股票池扩展

- 系统先从开盘啦题材成分生成高置信白名单；
- AI只能从白名单中提出同逻辑股票、角色和依据；
- 系统再次校验股票代码、题材标签来源和置信度；
- 通过校验后自动加入题材股票池；AI自行创造或白名单外的代码全部丢弃；
- 触板股票始终保留原始封板与炸板证据。

## 自动入库与推送

进入早期观察或正式题材后：

1. 保留共同事件首次达到4票门槛的交易日为Day 1；
2. 保存准入审查、新颖性、催化、持续天数、龙头空间、反证与扩展股票；
3. 早期观察不生成正式评分；正式题材生成Heat、Persistence、Entry Risk；
4. 分别发送“早期观察”或“正式题材”企业微信群机器人消息，包含触发、核心股票、催化、持续天数、龙头候选和情景空间；
5. 后续在08:40、10:30、13:30、15:30更新新闻催化列表。

## 题材库交互

- 已确认题材可置顶，置顶题材优先排序；
- “移除”采用可恢复归档，不永久删除历史；
- 股票行情榜与新闻催化分别折叠，展开状态保存在当前设备；
- 股票始终按当前涨幅纵向降序，显示当前涨幅、入库后累计涨幅、连板、流通市值、封板顺序和带动数；
- 股票行可加入测试票池，独立验证题材识别后的T+1开盘买入、T+2开盘/最高价表现；
- 已归档题材可在筛选器中恢复。
- 发现页默认显示早期观察，并可切换“审查中”“未入池”“全部审查”；未入池记录默认只显示题材名称，点击后展开最终状态与原因。

## 故障告警

交易日历、股票池、涨跌停价、日度指标、开盘啦数据、实时行情、AI准入和新闻更新失败均写入预警表并尝试企业微信群机器人推送。机器人发送失败时记录阶段、`errcode`、建议及最近成功时间；微信不可用期间无法通过同一微信通道报告其自身故障，因此网页和日志是必要的备用可见入口。
