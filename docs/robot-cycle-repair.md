# 机器人周期漏跟踪修复

## 生产证据与根因

2026-10-16至10-28的只读审计表明，机器人并非从未被识别：10-16曾通过正式准入，
10-19也有正式准入与通知记录。低空和机器人没有互斥规则。
真正的输入断层是10-19至10-28保存的247个发现trace中主板强势股始终为0，
输入全部来自创业板。目标主板股票因此没有进入这段时间的强势股候选集合。

代码中官方涨停价只在启动和收盘时同步，盘中主板兜底却只读取当日涨停价。
常驻进程跨日后可能缺少新交易日的涨停价，主板无法生成触板信号。
这条路径已用同一进程跨两个交易日的回归复现。历史导出没有按日涨停价覆盖，
因此不能仅凭旧审计证明每一天缺失的唯一原因都是该路径。

KPL榜单是延迟日度源，官方口径为交易日06:00更新前一交易日，周六更新周五数据。
当日反复查询空榜不能证明市场没有主板强势股；旧调度也缺少独立的次日补录任务。
来源：[KPL榜单](https://tushare.pro/document/2?doc_id=347)、
[每日涨跌停价格](https://tushare.pro/document/2?doc_id=183)。

第二个问题是把“新事件能否准入”当成“市场方向是否仍值得跟踪”。
新增事件被判为`old_rotation`，或首次四票的图谱验证被拒绝时，
市场共振记录可能缺席；已归档的机器人事件也没有独立的方向跟踪视图。
旧审计无法证明归档操作者，不能推断是系统自动归档。

另发现三个确定性问题：同名族节点被较小节点覆盖、单批20节点后的候选被截断、
多个板数解析器把“4天3板”拼成43。这些问题会缩小候选或扭曲市场结构。
置信度0.96与96混用则可能变成错误的低分拒绝。

## 修复后的行为

1. 每个交易日检查主板官方涨停价，09:00后不足95%覆盖时每5分钟重试。
   返回日期不符、非正数、非有限价格不计入。95%用于数据完整性诊断，题材门槛仍是4股。
   采集后的实际主板行情覆盖也需达95%，否则健康页、采集结果和页面明确显示待补。
2. 当日KPL标记`pending_publication`，不把尚未发布当成源故障。
   次日06:10后独立补最近两个已结束交易日的涨停价、KPL、概念和日线；失败30分钟后重试。
   周六也能补周五；成功状态持久化，重启后不重复已完成任务。
3. 日线重建的主板触板证据记录真实补录时间，封板时间和理由未知就保留未知。
   已有盘中或KPL证据优先，补录不覆盖。这个源修复任务不调用AI、不补发历史机会通知。
4. 本地强势股先写市场周期，再进入原图谱验证与事件准入。
   即使AI返回空结果或拒绝新增催化，达到四票的市场方向仍有可见的市场观察。
   机器人/人形机器人、低空/eVTOL采用小范围确定性别名关联；不同方向可以并存。
   周期ID由方向与首次观察日期决定，不随AI名称或每天的事件ID变化。
5. 展示每日强势股数、已知连板梯队、新增/延续强势股与板位提高数量。
   这不是核心股角色迁移或资金模型。数据缺失时标记“数据待补”，不推断退潮；
   后续恢复时不跨缺失日计算晋级。此前日线和官方涨停价完整时，可估计当前连续板位并标注，
   缺失时保持未知。“4天3板”保留窗口事实，不冒充连续板数。
6. 同名节点选用成员更完整的既有本地节点，不拼接任意股票池。
   原有最多30个本地节点按每批20个完整验证，未改四票或AI白名单限制。
7. AI提示明确`confidence_scale=0_100`。显式`0_1`允许按声明换算；
   未声明量纲的0到1小数视为格式错误，保留技术失败并走原重试流程，不保存低置信度业务拒绝。
   显式`0_100`下的0.96仍是低分，绝不擅自提高。明确的`old_rotation`不能被历史窗口兜底强制准入。

市场周期不是正式题材，归档事件只关联历史信息，不自动恢复、不重新推送。
2–3股本地观察继续不调用AI、不通知；四票、固定候选、新闻验证与全部正式准入条件保留。
猪肉/生猪的正式theme family逻辑未改。未加入Level-2、历史桥接成功率、交易计划等P1内容。

## 留痕与排查

全部复用现有`metadata`、`service_runs`及行情表，无新增表、字段或migration。
新增metadata键包括：

- `daily_limit_readiness:YYYYMMDD`、`daily_limit_attempt:YYYYMMDD`：覆盖和限频。
- `market_signal_coverage:YYYYMMDD`：实际行情可用性与分市场强势输入数。
- `kpl_concept_coverage:YYYYMMDD`：概念同步状态，空结果与接口失败分别保存。
- `completed_sources:YYYYMMDD`：次日补录状态、尝试时间、各源结果。
- `market_cycles_v1`：最多120个方向、每方向最近10个观察日；页面最多8个周期，成员展示有上限。

原`discovery_trace`继续记录源覆盖、节点验证及桥接决策，原`admission_trace`保存准入结果。
只读审计现在额外导出上述日度源状态、当前存储涨停价覆盖、分市场强势股数、市场周期快照，
以及题材归档/更新时间。当前存储覆盖不能替代当时盘中快照，归档时间不代表操作者。

```bash
.venv/bin/python -m stocktopic.discovery_audit \
  --dates 20261016 20261019 20261020 20261021 20261022 20261023 20261026 20261027 20261028 \
  --names 襄阳轴承 大业股份 光洋股份 东贝集团 凯众股份 万向钱潮 宁波东力 东安动力 保隆科技 万丰奥威 \
  --keywords 机器人 人形机器人 减速器 轴承 物理AI 低空 飞行汽车 \
  > robot-cycle-audit.json
```

审计不联网、不调用AI、不迁移或写库。旧日期没有新增留痕时显示缺失，不补造历史状态。
历史补录的`available_at`、`synced_at`采用实际可得时间，不能当作当时可交易信号。
本修复的回归使用合成数据和假AI，验证机制正确性，不声称已完成整轮行情的逐时点回测。

## 发布验证

合并后在Mac mini项目目录执行既有升级流程：

```bash
git pull --ff-only
./scripts/install_macos.sh
./scripts/doctor.sh
curl -sS http://127.0.0.1:8765/health
```

交易时段检查`daily_limit_readiness.ready`和`market_signal_coverage.mainboard_available`。
主板强势数为0可能是正常市场结果；应结合有效涨停价和实际行情覆盖判断，不能仅凭零涨停告警。
非交易时段不调用实时行情。页面市场周期需新版本开始观察后形成，不会伪造升级前的周期历史。
现有真实凭据与数据库由安装流程复用，仓库不存储Webhook或API Token。
