# 三源资金流（moneyflow_v1）

## 范围与调度
沿用数据库 `status=confirmed` 的正式题材判定以及 MarketClock/交易日历。采集每个正式题材所有 `active` 成分股，跨题材去重请求；观察池、测试池和归档题材不会新增请求。

上海时间9:30–11:30、13:00–15:00按15分钟槽执行，排除集合竞价、午休、非交易日及未知日历。盘中先用首只目标股验证东方财富接口，缺字段、空序列、跨日/超过20分钟/未来时间戳、金额关系不符均不接受数值。首股探测失败时该批标记不可用，下个15分钟槽重新探测。快照为当日累计净额，绝不将各槽相加。

盘后17:10起执行，缺源每15分钟重试至当日结束。成功源缓存复用，单源失败不阻塞其他源。服务须保持运行；跨日长时间停机期间未采集的历史不自动用当前成分回填。对没有当时成分记录的日期不制造题材回测数据。

## 金额及一致性
所有金额统一为元，原始响应保留。Tushare原始金额单位万元，乘10000：
- 大单净额 = buy_lg_amount − sell_lg_amount，20万≤成交额<100万。
- 超大单净额 = buy_elg_amount − sell_elg_amount，成交额≥100万。
- 主力净额 = 大单净额 + 超大单净额。**不使用 net_mf_amount 代替主力净额**。
- 东方财富盘后使用moneyflow_dc：net_amount为主力净额；buy_lg_amount、buy_elg_amount已是净额。
- 同花顺moneyflow_ths：buy_lg_amount为今日大单净额，作为主力方向代理。没有可比的超大单拆分，因此大单、超大单标准拆分为null；不使用net_d5_amount（五日）或net_amount（整体净流入）冒充当日主力。

三源金额无须一致。净额>0流入、<0流出、=0中性；缺失为unknown。共识度=同方向最多源数/3×100%，同时披露有效源数。三源完整且同向才“方向确认”；三源中性标记中性；缺源为待确认；方向不同单独保留分歧标记。真实性字段仅表示方向交叉验证，不证明机构身份或交易行为真实性；三套统计通过同一个Tushare传输渠道获取，不应当作三个独立网络渠道。

## 题材与历史
同一题材成员去重求和；任何成员缺源则该源的完整题材净额为null，显示覆盖率。资金广度=有Tushare正主力净额的成员数/全部成员数；数据不全明确标注。核心沿用现有leader_rank=1，不重新定义核心股；核心一致性为这些核心成员与题材主力方向一致的比例，缺数不计算。

flow_history为追加历史表，存个股/题材、日期、槽、采集完成时间、三源原始/标准字段、共识与版本。题材还保存当时全部成员和核心列表；同日盘后重试沿用首份盘后成员快照。旧版本不会被覆盖。

已认证接口：
- GET /api/v1/fund-flow/stock/600519.SH?trade_date=20260904
- GET /api/v1/fund-flow/theme/1?trade_date=20260904
- 可选as_of：使用记录的captured_at格式（上海时区ISO时间，含微秒）限制当时可知结果。结果按时间倒序。
- POST /api/v1/admin/refresh-fund-flow/close 或 intraday，沿用认证与防CSRF检查，不绕过交易时段。

## 兼容迁移与回滚
启动时将旧level2_reports和fund_flow_updates表重命名为legacy_order_flow_reports和legacy_order_flow_updates，仅作隔离历史留存；新建flow_history。迁移幂等，旧50万门槛数据不转成20万新口径，不进入新展示。旧提供商、配置读取、安装询问、采集入口和前端被移除。旧HTTP分析入口返回404。

升级前停止服务并备份整个SQLite数据库（含正常关闭前的WAL；可用SQLite backup接口制作一致性备份）。升级后按原入口 `.venv/bin/python -m stocktopic` 启动。回滚时停止服务、恢复升级前代码与数据库备份；不要直接让旧代码读取已迁移库。

## 实测边界（2026-09-06）
东方财富stock/get请求可连接但缺资金字段、f124=0；fflow/kline/get返回股票与9月4日时段信息但klines为空；另一股票探测返回空连接响应。结论：当前环境未验证可用的盘中资金数据，不能声称盘中采集已实盘通过。保留运行时探测及校验，只有有效数据才接受。该接口非有保障的商业API，字段映射仍需交易时段有效样本确认。

本地项目无已配置的Tushare生产凭据；三源账户权限与真实盘后数据仍需在原运行环境验证。官方文档列moneyflow至少2000积分、DC与THS至少5000积分，实际以账户授权为准。
